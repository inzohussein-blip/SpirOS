# 🗺️ خريطة طريق SpirOS (النسخة 2)

> مساحة ثانية معزولة ومشفّرة داخل هاتفك، بدون روت، على **أندرويد 14 وما بعده، وعلى أي واجهة** (MagicOS، One UI، HyperOS، ColorOS، Pixel...).

## القرارات المعتمدة

| البند | القرار |
|---|---|
| الأهداف | تطبيقات أندرويد معزولة، وخزنة ملفات وصور مشفرة، وتصفح خاص ضد التتبع، ونظام كامل (VM) |
| المسار الهندسي | **مساران متوازيان**: المسار A (المساحة المعزولة) هو المنتج الأساسي، والمسار B (محرك QEMU) مسار بحثي |
| بيئة التطوير | **الهاتف فقط**: كل البناء يتم على GitHub Actions، ويُحمَّل الـ APK من صفحة Actions |
| النشر | استخدام شخصي + مفتوح المصدر بترخيص **GPL-2.0-or-later** (متوافق مع QEMU) |
| الحزمة | `com.spiros.app` · Kotlin · Jetpack Compose · **minSdk 34 (أندرويد 14)** · targetSdk 35 |
| التوافق | **نظام عام**: لا كود خاص بشركة أو واجهة؛ كل ميزة تُكتشف أثناء التشغيل ولها بديل |

## مبدأ "النظام العام" (يعمل على أي واجهة)

1. **واجهات أندرويد الرسمية فقط** (Keystore، BiometricPrompt، DevicePolicyManager، VpnService). لا اعتماد على ميزات خاصة بشركة معينة.
2. **فحص القدرات أثناء التشغيل**: شاشة "توافق الجهاز" (`compat/DeviceCompat.kt`) تسأل النظام عمّا يدعمه، ولا تفحص اسم الشركة.
3. **بديل لكل ميزة**: إذا كانت الواجهة تمنع Work Profile، تستمر الخزنة والمتصفح والدرع داخل SpirOS نفسه. وإذا لم توجد بصمة، يعمل الفتح بالرمز. وإذا لم يوجد تسريع للمحاكاة، يعمل المختبر بالمحاكاة البرمجية.
4. **أندرويد 14 كحد أدنى**: يعطينا BiometricPrompt المدمج، ومستويات أمان المفاتيح، و`ImageDecoder`، وواجهات Work Profile الحديثة، دون مكتبات توافق إضافية.

## لماذا مساران؟

بدون روت لا يستطيع أي تطبيق استخدام تسريع العتاد للأجهزة الوهمية (KVM/pKVM/AVF).
لذلك QEMU يعمل بالمحاكاة البرمجية (TCG)، وأندرويد كامل بداخله سيكون بطيئًا جدًا على أي هاتف متوسط.
**الحل:** نبني المنتج اليومي على آليات أندرويد الرسمية للعزل (Work Profile)، ونطوّر محرك QEMU بالتوازي
لتشغيل نظام لينكس خفيف، ونقيس أداءه بأرقام حقيقية قبل أي محاولة لتشغيل أندرويد كامل.

## الهيكل

```
SpirOS.apk
├── 🔐 Vault        مصادقة PIN/بصمة، مفاتيح Android Keystore، تخزين مشفر، FLAG_SECURE
├── 🏠 Launcher     الواجهة الثانية: تعرض فقط تطبيقات المساحة المعزولة
├── 🧱 Space        Work Profile، و SpirOS هو Profile Owner فيه
├── 🛡️ Shield       VpnService محلي لحجب المتتبعات (DNS)، وتعطيل خدمات جوجل داخل المساحة
├── 🌐 Browser      متصفح خاص (GeckoView أو WebView مقسّى) يُمسح عند الإغلاق
└── 🧪 Engine       QEMU عبر NDK/JNI ← لينكس خفيف ← عرض في SurfaceView
```

```
app/src/main/
├── java/com/spiros/app/
│   ├── ui/        شاشات Compose
│   ├── vault/     المصادقة والتشفير            (المرحلة A1)
│   ├── space/     إدارة Work Profile            (المرحلة A2)
│   ├── launcher/  الواجهة الثانية              (المرحلة A3)
│   ├── shield/    VPN و DNS                    (المرحلة A4)
│   └── engine/    واجهة Kotlin لمحرك QEMU      (المسار B)
└── cpp/
    ├── spiros_jni.cpp   جسر JNI
    └── qemu_core/       كود QEMU المعدّل        (المرحلة B1)
```

## المسار A: المساحة المعزولة (المنتج)

### A1: الخزنة (Vault) ✅
- [x] رمز PIN (من 6 إلى 12 رقمًا) بلوحة أرقام خاصة، لا تمر عبر لوحة مفاتيح النظام
- [x] مفتاح بيانات عشوائي (AES-256) مغلّف بمفتاح مشتق من الرمز (PBKDF2، 200 ألف تكرار)، ثم مغلّف مرة ثانية بمفتاح عتادي من Keystore، فلا يمكن تخمين الرمز إلا على هذا الهاتف نفسه
- [x] الفتح بالبصمة عبر `BiometricPrompt` مع مفتاح مرتبط بالبصمة، يُلغى تلقائيًا عند إضافة بصمة جديدة
- [x] قفل فوري عند مغادرة التطبيق، ومسح المفتاح من الذاكرة
- [x] تشفير الملفات والصور والفيديو بـ Tink (AES-256-GCM-HKDF بمقاطع 1 ميغابايت)، والأسماء والأنواع داخل فهرس مشفّر
- [x] استيراد من أي مصدر (منتقي ملفات النظام)، مع خيار حذف الأصل، وتصدير نسخة مفكوكة التشفير
- [x] **رمز الطوارئ**: يمسح الخزنة بصمت ويفتح خزنة فارغة جديدة
- [x] 5 محاولات مجانية، ثم تأخير متصاعد (30 ثانية ← ساعة كحد أقصى)
- [x] شاشة توافق الجهاز (تمهيد للمرحلة A2)
- [ ] تغيير الرمز، ومهلة قفل قابلة للتعديل، ومشغّل فيديو داخلي

### A2: محرك العزل (Work Profile) ✅
- [x] إنشاء المساحة عبر `ACTION_PROVISION_MANAGED_PROFILE`، ويصبح SpirOS هو Profile Owner بداخلها
- [x] دعم مسار أندرويد 12 وما بعده (`GET_PROVISIONING_MODE` و`ADMIN_POLICY_COMPLIANCE`)
- [x] قناة أوامر من الملف الأساسي إلى المساحة (cross-profile intent filter) محمية بمفتاح عشوائي يُتبادل عند الإنشاء. لا تُرسل الأوامر إذا كان هناك تطبيق آخر يمكنه اعتراضها
- [x] عرض تطبيقات المساحة وتشغيلها عبر `LauncherApps`، وهي واجهة عامة تعمل مع أي تطبيق وعلى أي واجهة
- [x] استنساخ التطبيقات من الهاتف إلى المساحة (`installExistingPackage`): نفس التطبيق، ببيانات وحسابات منفصلة
- [x] تجميد تطبيق أو كل التطبيقات (`setPackagesSuspended`)، والإزالة من المساحة (حذف صامت، أو إخفاء إن رفض النظام)
- [x] منع النسخ واللصق بين المساحة والهاتف، وإخفاء أيقونة SpirOS داخل المساحة
- [x] حذف المساحة كاملة. مسح الخزنة أو رمز الطوارئ يحذف المساحة أيضًا
- [x] استئناف المساحة إذا كانت متوقفة، أو إرشاد المستخدم لفعل ذلك من الإعدادات السريعة
- [ ] تثبيت APK مباشرة داخل المساحة، وتجميد تلقائي عند قفل SpirOS
- ⚠️ إذا كانت الواجهة تمنع Work Profile أو يوجد ملف عمل آخر، تشرح شاشة المساحة السبب، ويعمل SpirOS بالبديل الداخلي

### A3: الواجهة الثانية (Launcher)
- شاشة رئيسية خاصة بـ SpirOS تعرض تطبيقات المساحة فقط (`LauncherApps` + `UserHandle`)
- تصميم مستقل (خلفية، أيقونات، شريط بحث)، ولا تظهر إلا بعد المصادقة
- اختصار لإخفاء أيقونة SpirOS نفسه (تمويه كتطبيق آلة حاسبة: اختياري)

### A4: درع الخصوصية (Shield)
- `VpnService` محلي داخل المساحة يحجب نطاقات المتتبعات والإعلانات (قوائم مفتوحة مثل StevenBlack وOISD)
- DNS مشفر (DoH) لمزود تختاره
- تعطيل Google Play Services والتطبيقات المرتبطة داخل المساحة
- مثبّت بديل: F-Droid / Aurora Store داخل المساحة
- لوحة تعرض كم متتبعًا حُجب ولأي تطبيق

### A5: المتصفح الخاص
- متصفح داخلي (GeckoView: محرك Firefox، أقوى في الخصوصية من WebView)
- وضع "لا أثر": لا سجل ولا كوكيز بعد الإغلاق، مع حجب المتتبعات عبر Shield

## المسار B: المحرك الوهمي (بحثي، بالتوازي)

### B1: QEMU على أندرويد
- بناء QEMU (`qemu-system-aarch64`) كمكتبة مشتركة لـ arm64-v8a عبر NDK. سنعتمد على سكربتات مشروع **Vectras VM** كمرجع لأنه ما زال يُطوَّر، بخلاف Limbo
- البناء يتم داخل GitHub Actions، وتُخزَّن الملفات الناتجة كـ cache
- جسر JNI: `startVm(args)`, `stopVm()`, `sendKey()`, `sendPointer()`

### B2: نظام ضيف خفيف
- **أولًا:** Alpine Linux aarch64 (حوالي 60MB) بواجهة طرفية، لقياس سرعة الإقلاع على جهازك
- **ثانيًا:** واجهة رسومية خفيفة (مثل Xfce) عبر VNC أو SDL2
- يُنزَّل النظام عند الحاجة إلى `filesDir` (لا يُضمَّن في الـ APK)، مع التحقق من SHA-256
- قرص الضيف يُشفَّر (LUKS داخل الضيف، أو qcow2 بتشفير AES) بمفتاح من الخزنة

### B3: العرض والإدخال
- عرض الإطارات (framebuffer) في `SurfaceView` عبر `ANativeWindow` (أو SDL2)
- لوحة مفاتيح ولمس، ومشاركة الحافظة بشكل اختياري

### B4: قياس وقرار
- نقيس زمن الإقلاع واستهلاك البطارية والذاكرة على جهازك
- بناءً على الأرقام نقرر هل نجرّب أندرويد مصغّرًا (AOSP/Cuttlefish بدون واجهة) أم نكتفي بلينكس
